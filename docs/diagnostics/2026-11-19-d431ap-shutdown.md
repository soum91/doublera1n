# iPhone 11 Pro Max (d431ap / 24A446): second-Data unexpected shutdown

This is separate from the experimental Pico standalone NAND boot. The already installed second Data environment previously ran with Sileo/SSH, then unexpectedly powered off or appeared to shut down after some time. The earlier `a492ffd` USB reset retry changes **only the initial USB handoff**, not any on-device runtime power-off.

## Capture on the Mac while the installed second Data is SSH reachable

Keep your successfully working `~/doublera1n-usb-537622e` checkout untouched. In a *separate* latest `~/doublera1n-pico` checkout:

```sh
cd ~/doublera1n-pico
git pull --ff-only
python3 standalone/pico2/collect_shutdown_diagnostics.py
```

The collector uses the **existing** `./dualboot.py ssh` in `~/doublera1n-usb-537622e`; it never calls install, boot, reboot, mounts or NVRAM changes. It requires the phone to be USB-connected and booted into DataB with working SSH. It collects local private `~/Desktop/doublera1n-shutdown-<UTC time>/` with `system-snapshot.txt`, `inventory.txt`, `README.txt` and up to 12 panic/watchdog/Jetsam files (2 MiB cap each). Run it soon after a successful desktop boot, and run it again when the device is reachable after a failure to compare evidence. If a crash prevents SSH, no report can be collected by this script until a bootable environment is reachable.

If the old checkout has a different path:

```sh
python3 standalone/pico2/collect_shutdown_diagnostics.py \
    --checkout /path/to/previous-successful-checkout
```

## Interpret before altering the kernel

1. **A new `panic-full` with `panicString`, watchdog or kernel backtrace:** likely a kernel/watchdog crash; correlate its timestamp with the failure and inspect panic details, subsystem and boot arguments.
2. **JetsamEvent only, no panic:** indicates memory pressure occurred, but not proof the entire phone powered off.
3. **No panic report and device goes completely dead:** investigate power/battery/USB and whether it rebooted to stock iOS; collect Mac USB logs. An electrical power loss may not leave an IPS panic.
4. **Reboots only while DataB runs:** compare a known-good stock-iOS session, injected tweak/launchd changes and the precise installed build. Do not randomly modify kernel/power-management patches before obtaining evidence.

Do **not** treat 'LED success', host USB commands, or absence of panic files as proof the boot chain is healthy. The report contains potentially sensitive device details. Keep it off public Git, Actions artifacts and issue comments; review/redact before sharing excerpts.
