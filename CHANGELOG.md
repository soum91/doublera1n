# Changelog

## Unreleased

- Merged the working `537622e` desktop installer/boot code and Pico 2 build documentation while retaining the later NAND transport hardening and regression tests from `main`. Restored USB setup/ticket and SSH helper scripts, OS2 prototype code, firmware profiles and compiled supporting payloads. NAND private exporter can use the exact successful local firmware profile with `--profile-dir` and the installation checkout workspace root. Existing DataB and stock iOS are unchanged. A personalized Pico UF2 was compiled and validated **offline only**, remains private, and has NOT been flashed or boot-tested.


- Added the missing `device_identify` declaration when integrating the Pico standalone add-on. This addresses the GCC 15 implicit-function-declaration error in its main entry point. Physical boot and the final ARM firmware build remain unverified.

- Implemented a device-untested Pico 2 NAND reboot candidate: resolved the enabled ramdisk configuration flag, traced APFS Preboot role and BootManifestHash prefix, generated transient kernel/DT/TC/TXM/ramdisk path overrides, and guarded iBoot's false-success ramdisk load. Added private installed-workspace retagging with exact firmware/patch-plan and ticket checks, an EP0-only Pico transport with before/after device binding, and reviewed standalone-source integration that keeps private headers out of Git and labels handoff as unverified. Added ARM64 emulation, C transport and integration tests. No phone staging, physical boot, firmware build or UF2 is claimed; see `standalone/pico2/NAND_BOOT.md`.

- Fixed the existing manual iPhone 11 Pro Max precheck workflow being rejected at YAML validation: moved its `RUNNER_TEMP`-based workspace setup into a runner step instead of using the unavailable `runner` expression context in job-level environment evaluation. The firmware job remains manual and does not connect to a phone.

- Continued the Pico 2 no-microSD investigation against the exact Apple d431ap/24A446 firmware. Added reproducible manifest/digest/hash-bound binary analysis, concrete filesystem/ramdisk loader references, storage measurements and CI JSON-only audit output. The candidate preparer now rejects other or previously patched raw iBoot images. All 61 offline tests passed and the existing kernel/TXM/DeviceTree plans were checked against the firmware. The shared ramdisk path has unresolved runtime gates and volume access; no phone writes, standalone boot or UF2 is claimed. See `standalone/pico2/BINARY_FINDINGS.md`.

- Added a host-only Pico 2 internal-storage `fsboot` proof-of-concept in `standalone/pico2/nand_fsboot.py`, with source-audit preconditions, a fail-closed raw-iBEC patch preparation, nine offline tests, and documentation of why the existing installed `DataB` cannot simply replace the separate jbinit ramdisk/firmware chain. This **does not generate flashable UF2**, has never been run on an iPhone, and makes no device, NVRAM, Preboot, installer, or existing desktop boot changes. See `standalone/pico2/NAND_FSBOOT.md`.

- Added an experimental Raspberry Pi Pico 2 standalone-rebooter foundation under `standalone/pico2/` for already-installed d431ap/24A446 OS B. The read-only exporter packages the existing personalized `osbjb` boot chain for external microSD; the portable C parser and CRC preflight verify exact stage order and integrity. Nine host tests and a strict native C build pass. This is **not flashable UF2 firmware**: RP2350 SD and USB Recovery bulk-upload transport are still missing. No installer, phone filesystem, or existing desktop boot code changed.

- Switched the standalone probe build to native ad-hoc `codesign` with DER entitlements and strict signature verification after the first V2 build compiled but failed signature verification. CI now also checks the embedded USB/network entitlements and stops on inspection errors rather than hiding them behind `tee`.

- Corrected a missing prerequisite in the USB diagnostic: the replacement `restored_external` previously opened a TCP socket without configuring device-mode USB. V2 initializes loopback and requests IOKit's `standardMuxOnly` device descriptor, with bounded controller retries and explicit status codes. It has separate USB/network/platform entitlements and no disk entitlement. Missing private APIs fail visibly instead of causing an early dynamic-link failure. The host requires the V2 banner and the ramdisk builder refuses the obsolete V1 binary. Added executable C tests for successful initialization, missing APIs/descriptors, controller timeout, configuration rejection, and delayed controller arrival. The macOS workflow builds, verifies, and publishes the signed V2 binary. This fixes a concrete diagnostic defect; successful kernel boot, USB enumeration on iOS 27, and jailbreak installation remain physically unverified.

- Found a boot-image staging mismatch against the public A12/A13 SSH ramdisk reference after another physical USB-return failure. Added an opt-in `probe-usb --variant reference-order` that keeps the previous lean-kernel read-only probe but stages SPTM/TXM, RestoreSEP, peripherals, DeviceTree, trust caches, ramdisk, and kernel in the reference order, with controlled settle delays. Added regression tests for exact order and refusal in installer/OS B contexts. The old chain and installer are unchanged; this path has not been tested on the device and is **not** a confirmed jailbreak.
- Added two read-only iPhone 11 Pro Max kernel diagnostic plans, `probe-usb --variant stock-kernel` and `--variant lean-kernel`. The first retains the signed stock Apple kernel, the second limits setup-kernel changes to the seven AMFI trust-cache and launch-constraint records; both retain patched TXM, full firmware, and explicit volatile `rd=md0` boot arguments to isolate the kernel's effect on the black-screen failure. Unknown or unguarded patch variants are rejected. Only explicit `--boot` sends anything to the device; installation paths and installed filesystem behavior are unchanged. These are unverified experiments, **not** a working jailbreak claim.
- Fixed panic/reset triage after inspecting the first physical-device export: `idevicecrashreport` gave all files the same copy time, so reports are now sorted by the original embedded event date. `ResetCounter` output now includes the actual boot-failure count, raw boot-stage code and reset fault flags, without pretending those undocumented codes have known meanings. The `analyze` command can read a ZIP directly without extracting or writing files.
- Added `scripts/boot_failure_triage.py` for a new diagnostic path after repeated black-screen boots. It copies existing iPhone crash reports with libimobiledevice's `--keep` option (never removes them), or analyzes manually exported reports completely offline. Its output gives report timestamps and likely SEP, TXM/SPTM, trust-cache, APFS, or display clue families without printing sensitive report contents. It explicitly warns that early failures may leave no panic file. No firmware, ramdisk, DFU, installer, or boot-chain behavior changes.
- Recorded the d431ap/24A446 native-iBEC host result: its patched bytes matched patched iBSS, so the experiment stopped before boot. No physical iBEC variant is needed for this finding.
- Added a host-side `native-ibec` diagnostic variant that separately patches the firmware's **actual** iBEC executable instead of silently substituting patched iBSS bytes. It fails before physical boot if they are identical, so the user does not repeat a redundant experiment. Existing installation boot-chain behavior is unchanged.
- Documented two physical failures of the volatile-bootargs variant on d431ap/24A446: iBEC accepted `setenv`, but no custom listener was reachable after `bootx`. This rules out command rejection, not a kernel panic or ramdisk launch issue.
- Added a separate, opt-in USB probe variant (`--variant bootargs`) that explicitly sets **volatile** `rd=md0 -v debug=0x2014e` on the patched iBEC immediately before `bootx`, detecting a rejected command instead of treating it as a successful kernel boot. The installation and existing boot variants remain unchanged.
- Recorded the iPhone 11 Pro Max 27.0.1 physical results honestly: the stock control rebooted to stock iOS, and the minimal-firmware probe still did not return a listener. Neither observation verifies a restore ramdisk boot or jailbreak.

- Added opt-in `probe-usb --variant stock` and `--variant minimal` diagnostics for the iPhone 11 Pro Max black-screen boot. The stock variant repackages Apple's unmodified RestoreRamDisk and RestoreTrustCache without injecting a binary and passively watches post-boot USB; the minimal variant removes peripheral firmware while retaining SPTM, TXM and both trust caches. Both reject implicit installation and require `--boot` before transmitting a chain. The standard installer and default probe behavior are unchanged.
- Added a host-side `rd=md0` artifact check before experimental boot, explicit Recovery/DFU exclusion from the stock USB observer, and offline checks that the stock baseline neither mounts nor injects into the ramdisk. Neither alternative is physically validated; seeing a USB product ID would not by itself prove successful ramdisk startup.
- Added read-only post-`bootx` diagnostics after the first physical iPhone 11 Pro Max trial reached `bootx` but produced a black screen and no USB probe response: the boot chain now reports the actual `irecovery -c bootx` exit/output and observes Apple USB product-ID transitions. A command being issued is no longer presented as proof that the custom kernel/ramdisk booted.
- The USB probe's timeout report now cross-checks raw Apple USB enumeration and `irecovery -q` status so a failed `usbmuxd`/`iproxy` handshake is distinguishable from disappearance from USB. The no-UART installer is still not implemented or validated.
- Fixed an early iBSS handoff diagnostic failure on Macs: `boot_chain.py` now uses the caller's virtual-environment Python for the `usbliter8ctl` sender, stops and prints its actual error if the send fails, and reports detected USB mode after Recovery timeout. Recovery A/B/C/D USB product IDs are recognized. This is not evidence of a successful physical boot or a completed jailbreak.
- Added an opt-in, read-only USB restore-ramdisk transport experiment for Macs whose pwnDFU boards expose no UART/CDC serial device. Its standalone ramdisk listener and host `iproxy` client test only a diagnostic handshake; no APFS volume setup or ticket extraction runs.
- Added a manual macOS workflow to build and sign the standalone diagnostic binary. Actual iPhone 11 Pro Max boot and USB return transport remain untested; the normal installer still requires UART.
- Included the workflow-built, signed diagnostic binary under `payload/setup/rdprobe`, eliminating manual artifact copying on Macs running the experiment.
- Added an iPhone 11 Pro Max (`d431ap`, `iPhone12,5`) firmware profile generated from iOS 27.0.1 (build `24A446`). All ten read-only firmware precheck stages passed; physical boot remains untested.
- Rejected 11 Pro-specific firmware path defaults for the Pro Max when the IPSW BuildManifest is missing.
- Added a Pro Max profile validator, identity and firmware-path regression tests, and a manual read-only macOS firmware precheck workflow.
- Documented iPhone 11 series requirements, firmware verification, and device-test limitations.
